## Context

While planning slice 01 of
[End-to-end tests for the critical journeys](../../tasks/20261103-2143-e2e-tests.spec.md),
four defects of the web build came up. React Native's `Alert.alert` does
nothing on React Native Web, so on the web:

- the brand suggestion screen validates and confirms silently: the user
  never learns that the brand is missing, that the suggestion was sent, or
  that it failed;
- ~~the admin suggestions screen asks for confirmation before rejecting or
  deleting through `Alert.alert` with buttons, so rejecting and deleting
  never happen on the web.~~ (struck 2026-11-03: wrong — the screen
  already branches on `Platform.OS === 'web'` and uses `window.confirm`.
  What remains is the duplicated platform branching, folded into one
  confirmation helper with behaviour unchanged.)

Two navigation defects come with them:

- a visitor who opens `/admin` while logged out gets the toast "Votre
  session a expirée" and a redirect, because the screen fetches admin data
  before knowing who is logged in;
- the web navbar has no link to the history, which only works by typing
  its URL.

## Scope

**Included:**
- Feedback that works on web, iOS and Android for the three brand
  suggestion messages, using the app's existing toast.
- Reject and delete confirmations that work on web, iOS and Android.
- `/admin` while logged out: a plain redirect to the login screen, with no
  toast and no admin request.
- A history link in the web navbar.

**Not Included:**

- e2e tests: slice 01 of the e2e task covers these journeys, and its
  branch merges with this one.

## Seams

- **Confirmation** — one cross-platform way to ask "confirm or cancel" and
  run the action on confirm: native alert on iOS/Android, a web-compatible
  dialog on web.
- **User feedback** — the existing toast (`src/components/reacticx/Toast`)
  for messages that need no answer.
- **Admin screen guard** — the admin data is fetched only once the session
  is known and is an admin's, on `/admin` and on `/admin/suggestions`
  (the second added 2026-11-03: same defect, same fix).

## Architecture

**System design:** a small confirmation helper or component, with a web
variant (`.web.tsx`, as the codebase already does for screens), replaces
the `Alert.alert` calls that take buttons. The brand suggestion messages
move to the toast. The admin screen gates its query on the auth state that
`useAuth` already exposes.

## Implementation Decisions

- Reuse what exists (toast, `useAuth`, the `.web.tsx` platform-file
  convention) before adding anything. No new UI library.
- Add no `testID` here: slice 01 of the e2e task adds them on these
  screens, and doing it twice makes the merge harder.
- 2026-11-03, human ruling (option A): the three brand suggestion messages
  are a native alert (`Alert.alert`) on iOS and Android, and a toast on
  web, through one platform-split helper (`showFeedback`, `.web.ts`
  convention, like `confirmAction`). Reason: the toast viewport lives in
  the root view, and an iOS modal screen would likely hide it. This
  replaces "the brand suggestion messages move to the toast" of the
  Architecture for native.

## Testing Strategy

- Unit tests (Jest, `jest-expo`) for the confirmation helper on each
  platform variant, and for the admin screen not querying while logged out.
  _(Amended 2026-11-03 by the Architect's ruling: the admin guard is tested
  through its pure functions, `resolveAdminAccess` and
  `resolveAdminRedirect`, not at screen level; the feedback helper is also
  tested on each platform variant.)_
- The visible behaviour on web is checked in the browser (§F browser check
  of `.agents/project.md`), then covered by slice 01's e2e journeys once
  both branches meet.
