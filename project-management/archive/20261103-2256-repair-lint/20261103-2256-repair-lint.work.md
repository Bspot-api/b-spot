`eslint-config-expo`'s own folder (where 8.56.1 is installed) gives **0

mobile green; no source file in mobile needs a change.

`eslint-plugin-prettier`, which mobile does not declare. They load only

- **The brand-resolution union is written a third time in
  `scan.service.ts`.** Fixed in `ceee50b`: `ResolvedBrandResolution` is
  now derived from `BrandScanResultDto['brandResolution']` with `Exclude`.

  `brandResolution` defaults to `'existing'` when no brand was found.**
  Fixed in `ceee50b`: `BrandLookup` is now a discriminated union of a
  resolved lookup (`brand: Brand` with its resolution) and an unresolved
  one (`brand: null` with the discovery message).
  `buildCompanyResult(lookup)` takes the resolved lookup only.

  Fixed in `84ee384`.
- **`suggestUnresolvedBrand(productDto, productDto.brandName, lookup)`
  repeats the brand name.** Answered: `ProductDto.brandName` is optional,
  and the argument carries the narrowed `string`. Removing it would bring
  back a non-null assertion or a second check.
- **Inline French messages remain in `scan.service.ts` and
  `brand-discovery.service.ts`** ("No hardcoded strings"). Answered: these
  lines existed before this task and were moved without being rewritten.
  Only the two messages the extraction merged became constants. Turning
  the rest into constants is outside a mechanical lint repair.
- **The test override departs from the 30-line rule in CLAUDE.md, which
  has no test exemption.** Answered: the Architect ruled the narrowing,
  and the reason is written in `apps/api/.eslintrc.js`. Recording the
  exemption in CLAUDE.md is left to the Architect, because CLAUDE.md is
  the human's file.
- **The scan-by-brand-name refusal is built inline, while scan-by-barcode
  uses `suggestUnresolvedBrand`.** Answered: the messages and the
  suggestion step differ, and the reviewer judged it acceptable.
- **`logPappersFailure` is a thin wrapper (Middle Man).** Answered by the
  reviewer itself: it removes a real duplication.
