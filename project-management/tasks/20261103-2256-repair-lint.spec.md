## Context

`pnpm lint`, one of the gate commands in §F · Gate commands of
`.agents/project.md`, is red at the base of every current branch, so no
task can meet its `suite-green` criterion.
- **Mobile:** `eslint-config-expo` 10 expects `@typescript-eslint` 8, but
  the app pins 6. Every file fails with "Definition for rule
  '@typescript-eslint/…' was not found" (94 errors).
- **API:** about 25 errors. Some are functions over 30 lines. The others
  are spec files and migrations outside the `tsconfig.json` the linter
  uses.
- The API's `lint` script runs with `--fix`, so a gate run rewrites files
  (prettier).

## Scope

**Included:**
- Aligning the mobile ESLint dependencies so its config loads.
- An ESLint tsconfig that covers the API's spec files, migrations and
  `test/`.
- Fixing the remaining real errors, or narrowing a rule with a written
  reason.
- A `lint` without `--fix`, plus a separate `lint:fix`.

**Not Included:**
- Changing the project's rules, such as the 30-line function limit, beyond
  a narrowing that is justified in writing.
- `apps/e2e`, which already lints clean.

## Acceptance Criteria

- [ ] **lint-green** — `pnpm lint` exits 0 from the repo root.
- [ ] **lint-is-read-only** — running `pnpm lint` leaves `git status`
  unchanged.
- [ ] **suite-green** — `pnpm test` and `pnpm build` pass.
