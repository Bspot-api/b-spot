`testID`. Messages are French, kept as named constants at the top of the
file that uses them (no inline literals in handlers).

### Confirmation seam — `src/components/confirm/`

Three files, following the `.web.tsx` platform-file convention already used
by `Toast.tsx` / `Toast.web.tsx` and `_layout.tsx` / `_layout.web.tsx`:

```ts
// confirmAction.types.ts
export interface ConfirmRequest {
  title: string;          // native alert title; unused on web
  message: string;        // the question, shown on both platforms
  confirmLabel: string;   // native button label; unused on web
  cancelLabel?: string;   // native, default 'Annuler'
  destructive?: boolean;  // native button style, default false
  onConfirm: () => void;
}

// confirmAction.ts      (iOS / Android)
export function confirmAction(request: ConfirmRequest): void;
//   Alert.alert(title, message, [cancel button, confirm button → onConfirm])

// confirmAction.web.ts  (web)
export function confirmAction(request: ConfirmRequest): void;
//   if (window.confirm(message)) onConfirm();
```

The type lives in its own file so the web file does not import from
`./confirmAction` (which Metro would resolve to the web file itself).
`window.confirm` is the "web-compatible dialog" of the spec's Architecture:
it is the browser's own, needs no UI library, and is what the screen
already does inline today (see Notes: contradiction with the spec).

`app/admin/suggestions.tsx`: `confirmReject` and `confirmDelete` in
`SuggestionItem` lose their `Platform.OS` branches and become one
`confirmAction({...})` call each. `Platform` and `Alert` leave the imports.

### User feedback — brand suggestion screen

`app/brand-suggestion/new.tsx`: the three `Alert.alert` calls become
`Toast.show(text, { type })` from `src/components/reacticx/Toast`, which
works on web (`Toast.web.tsx`) and native, and is mounted at the root
(`ToastProviderWithViewport` in `app/_layout.tsx`), so it survives the
navigation back.

| Case | Toast | Type | Then |
|---|---|---|---|
| empty brand | "Merci de renseigner le nom de la marque." | `warning` | stay |
| success | "Merci ! Ta contribution a bien été enregistrée." | `success` | leave the screen |
| failure | "Impossible d'envoyer la suggestion pour le moment. Réessaie dans un instant." | `error` | stay |

"Leave the screen": the native alert waited for OK before `router.back()`;
a toast needs no answer, so the screen leaves immediately after showing
it. On web the screen can be opened directly by URL with no history, so:
`router.canGoBack() ? router.back() : router.replace('/')`, extracted in a
small `leaveScreen()` local function. Default toast position (bottom),
default duration (3 s).

### Admin screen guard

1. `src/api/hooks.ts` — `useAdminSuggestions` gains an options argument:

   ```ts
   export function useAdminSuggestions(
     status?: SuggestionStatus,
     options?: { enabled?: boolean }
   ): UseQueryResult<BrandSuggestionListDto>;
   // useQuery({ ..., enabled: options?.enabled ?? true })
   ```

2. `src/features/auth/adminAccess.ts` — a pure decision, the testable heart
   of the guard:

   ```ts
   export type AdminAccess = 'pending' | 'login' | 'home' | 'granted';
   export function resolveAdminAccess(auth: {
     isLoading: boolean; hasSession: boolean; isAdmin: boolean;
   }): AdminAccess;
   // isLoading → 'pending'; !hasSession → 'login'; !isAdmin → 'home'; else 'granted'
   ```

3. `app/(tabs)/admin.tsx` — `access = resolveAdminAccess({ isLoading,
   hasSession: session !== null, isAdmin })`;
   `useAdminSuggestions(undefined, { enabled: access === 'granted' })`;
   the redirect effect does `'login' → router.replace('/login')`,
   `'home' → router.replace('/')` (a logged-in non-admin keeps today's
   behaviour). With the query disabled, no 401 reaches the root
   `QueryCache.onError`, so no "session expirée" toast. The root layout's
   401 handling is left untouched: it stays right for a session that
   really expires.

4. `app/admin/suggestions.tsx` — same guard (pending a ruling, see open
   questions): `useAdminSuggestions(activeStatus, { enabled: isAdmin })`
   and the same redirect, since it calls the same hook unconditionally and
   shows the same toast when opened logged out.

`useAuth` itself does not change: it already exposes `session`, `isAdmin`
and `isLoading`, and its admin query only runs with a session.

## Notes & Snippets

### Contradiction with the spec

- **Moderation confirmations already work on web.** The spec's Context says
  reject and delete "never happen on the web" because of `Alert.alert`.
  On this branch `SuggestionItem` in `app/admin/suggestions.tsx` already
  branches on `Platform.OS === 'web'` and uses `window.confirm`, which a
  browser shows. The e2e work document's findings ("Findings in the code
  that touch the spec" of `01-web-playwright.work.md`) do not list this
  defect either. The plan still moves both confirmations behind the seam
  (removes the duplicated platform branch, gives it a test), but the
  behaviour on web will not change. For slice 01: Playwright dismisses
  `window.confirm` by default, so its journeys must accept the dialog
  (`page.once('dialog', d => d.accept())`).

### Other observations

- `app/(tabs)/admin.tsx` today redirects a non-admin, logged out or not,
  to `/`, not `/login`; the 401 from the unguarded query is what
  currently lands the visitor on `/login`, with the toast.
- `app/admin/suggestions.tsx` is already 356 lines, over the 300-line
  limit; this task removes about 20. Splitting it is out of scope.
- Logged out, `getSession` is expected to answer `null` (Better-Auth
  `get-session` returns 200 with `null`), so `useAuth` itself sends no
  401. Checked at the browser step.
